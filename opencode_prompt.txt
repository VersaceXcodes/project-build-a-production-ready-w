Add an admin-editable “Legal” section inside Admin → System Settings.

UI / Navigation
1) In /admin/settings, add a new top-level tab called “Legal” positioned next to “Audit Logs” (same tab style as existing tabs).
2) Inside the Legal tab, add sub-tabs:
   - Terms of Service
   - Privacy Policy
   - Refund Policy

Editing experience (Admin)
3) Each sub-tab must have:
   - A title header (e.g., “Edit Terms of Service”)
   - A rich text editor or Markdown editor (Markdown preferred)
   - Buttons: “Save” (publishes immediately) and “Preview” (shows public rendering)
   - Show “Last updated” timestamp + “Updated by” (admin user)

4) Terms of Service must support the current public layout that uses multiple sections (like Payment Terms, Tax/VAT Information, File Requirements, Refunds & Cancellations, Revision Policy, Turnaround Times):
   - Store Terms as structured sections (array of { id, title, contentMarkdown, order })
   - Admin can edit the content of each section
   - Admin can reorder sections
   - Optional: add/remove sections (but keep defaults)

5) Privacy Policy and Refund Policy can be single-document editors (one content body each), rendered with headings and lists.

Persistence / Data model
6) Persist legal content in the database (not hardcoded files). Either:
   A) A “legal_documents” table with rows for privacy/terms/refund, OR
   B) System settings keys like:
      - legal_privacy_markdown
      - legal_refund_markdown
      - legal_terms_sections_json
   Include: updatedAt, updatedBy, and versioning (at least keep the previous version for rollback).

Public site behavior
7) Public policy pages must render from the database content and update immediately after admin saves:
   - Terms of Service page (the existing “Policies & Terms” public view) should be driven by the saved sections.
   - Privacy Policy page should render saved Privacy content.
   - Refund Policy page should render saved Refund content.
   - Display “Last updated” on each public page using the saved updatedAt.

8) If database content is empty (first run), seed the editor with the current existing page content so nothing breaks.

Security / Safety
9) Only authenticated admins can access/edit Legal settings.
10) Sanitize rendered content (if using rich text) or safely render Markdown to prevent XSS.

Wiring / Routes
11) Keep existing public routes if they already exist; otherwise create:
   - /terms (or the existing Policies & Terms route)
   - /privacy
   - /refund-policy
12) Ensure footer/legal links point to the correct public pages.

Acceptance criteria
- “Legal” tab is visible in Admin → System Settings next to Audit Logs.
- Admin can edit Terms, Privacy, and Refund content and click Save.
- Changes instantly reflect on the public pages (no hard refresh required).
- Terms page keeps the same section-based layout and “Jump to Section” behavior, driven by the saved section data.
